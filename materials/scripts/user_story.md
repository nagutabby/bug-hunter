# ユーザーストーリー
## 聞き手の気持ちの変化
1. 具体的な困りごととそこから導かれる問題を理解し、問題に共感する
2. 結果の意味を理解し、手法に価値があると感じる
3. 課題と対処法の説明から、研究が完成した状態をイメージし、今後の展開に期待を持つ

## 1. 問題を認識してもらう
以下の事実について説明し、確かにそれが問題であると納得させる
- ソフトウェア開発において、時間とともにコードが複雑化し、保守が困難になる
- リファクタリング時にバグ混入のリスクがある
- 現在の静的解析ツールは単一時点での分析しかできない

## 2. 研究の必要性を理解してもらう
- 時系列変化を考慮した分析が重要であることを認識させる
- バグ予測精度が向上することの価値を理解させる

## 3. 研究手法を理解してもらう
- どのようなデータを用いた研究なのかを知ってもらう
- 変化量メトリクスという新しい特徴量を理解してもらう
- 機械学習による分析手法の概要を把握してもらう

## 4. 成果を確認してもらう
- 3つのプロジェクトでF1スコアが有意に向上したことを知ってもらう
- 特に、陰性クラスの予測精度が改善されたことを認識してもらう

## 5. 課題を認識してもらう
- 陽性クラスの予測が困難であることを理解してもらう
- バグ発生原因の多様性が予測を困難にしている可能性があることを知ってもらう

## 6. 今後の見通しを理解してもらう
- 因果関係の解明の重要性を知ってもらう
- 実用的なリファクタリング支援に発展する可能性を認識してもらう
